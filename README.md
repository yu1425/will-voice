# WILL Voice

WILL.tennisの開催を支えるスマホ向け進行アシスタントです。PCでも幅480pxの画面で表示します。

- `/flow`：自動進行 / 個別進行を切り替えて使用
- `/guide`：初めて使う運営担当向けの使い方
- `/chat`：うぃるに質問（現在はルールベースの返答）
- `/`：`/flow`に移動

## 起動

Node.js 18以上を用意し、以下を実行します。

```sh
npm install
npm run dev
```

ブラウザで `http://localhost:3000/flow` を開きます。iPhoneではSafariの共有メニューから「ホーム画面に追加」できます。案内を確実に流すには、進行画面を開いたまま使ってください。

## 標準2時間の自動進行

「開催設定」でコート数を選択し、右上の設定で「チャイムを試聴」と「テスト再生」を行い、「自動進行を開始」を押します。全体の自己紹介はゲーム前です。

| 経過 | 案内 |
| --- | --- |
| 00:00 | 開始あいさつ・ショートラリー |
| 00:05 | ボレーボレー |
| 00:10 | ロングラリー |
| 00:20 | クロスラリー |
| 00:30 | サーブ・リターン |
| 00:35 | サーブ・リターン交代 |
| 00:40 | 乱数表の説明 |
| 00:43 | 試合ルール |
| 00:46 | 自己紹介 |
| 00:50 | ゲーム開始 |
| 01:45 | ミニゲーム（リレーラリー） |
| 01:57 | 終了あいさつ・片付け |
| 02:00 | 進行完了（音声なし） |

上部に現在のメニュー、経過時間、残り時間、進捗、開始・終了予定時刻、次・その次の案内と切替までの時間を表示します。Date.now()と開始時刻から1秒ごとに計算し、一時停止時間を差し引きます。

- 「進行を一時停止」は時計と今の音声を止めます。「進行を再開」で時計が再開します。
- 「今の音声を止める」は音声とチャイムだけを止め、時計は続きます。次のメニューでは案内が流れます。
- タイムラインから移動できます。実行中は画面内に確認を表示し、移動すると時計も同期します。
- 2時間で無音の進行完了になります。操作ボタンの位置は変わりません。
- 個別進行へ切り替えても時計は続きます。その画面では自動の案内は鳴りません。
- 別ページに移動すると、音声・チャイム・遅延案内をキャンセルします。
- 戻る・reload時は現在時刻に追いつき、過去の音声をまとめて流しません。
- 開始時刻、一時停止時間、状態、発火済イベント、コート数をlocalStorageに保存します。保存データv1/v2は新フローへ移行します。
- ブラウザのバックグラウンド化・画面ロック中は自動案内を保証できません。復帰時は時刻だけ同期します。

## 個別進行

同じ原稿を12STEPとして選択し、任意のタイミングで再生します。「前へ」「次へ」やSTEP一覧で移動できます。音声操作は「案内を聞く」（再生後は「もう一度聞く」）と「今の音声を止める」の2つです。STEPを移動すると再生中の音声を止めます。

「タイマー・声かけ」は両モードで使えます。5分/10分を選び、開始・一時停止・再開・リセットを操作します。固定声かけとタイマー終了はずんだもんWAVで再生します。ページが非表示の間に終了したタイマーは、復帰時に遅れて鳴らしません。「開催設定」でコート数と一時的な原稿編集を行えます。編集済み原稿は選択した音声モードで合成し、STEP移動で編集を解除します。進行中のコート数は読み取り専用です。

## 原稿とずんだもん音声

共通原稿は `lib/flowScripts.json` です。表示文・時刻・STEP・コート数・録音パスをまとめています。

```
lib/flowScripts.json
  → lib/voicevoxText.ts で読み補正
  → lib/flowScripts.ts（displayText / voiceText）
  → lib/standardTwoHourFlow.ts（自動進行）
  → lib/tennisFlowScripts.ts（個別進行）
  → scripts/generate-flow-audio.mjs（音声生成）
```

新しい録音は `public/audio/flow/v2/` にあります。クロスラリー、サーブ・リターン、乱数表は1面/2面の文面を用意しています。12イベント＋3つの追加variant＋音声テストの16WAVです。

自動進行と未編集の個別STEPは生成済みのずんだもん音声を再生します。ローカルENGINEは再生時には不要で、Vercel Previewでも同じファイルを使用します。録音の再生失敗時は画面に案内し、標準音声へフォールバックしません。元の音声ファイルは残しています。

個別進行の固定声かけ6種類とタイマー終了案内も、`lib/flowCues.json` を原稿として `public/audio/flow/extras/` のずんだもんWAVを再生します。共通音量・再生中の音量変更・停止に従い、チャットの音声モードに関わらず録音を使用します。タイマー操作と声かけ操作は別ブロックです。タイマーの一時停止は残り時間を保持し、声かけの停止でタイマーを止めることはありません。

読み補正はVOICEVOX用の文だけに適用します。WILL.tennis→ウィルテニス、乱数表→らんすうひょう、4ポイント先取→よんポイントせんしゅ、2人→ふたり、3球→さんきゅう、1列→いちれつ、2本→にほん、3本→さんぼん、人を指す「方」→かた、初参加→はじめて参加などを補正します。「方向」「方法」「聞こえ方」は維持します。

### 音声の再生成

ローカルVOICEVOX ENGINEを起動し、`http://127.0.0.1:50021/speakers` が応答することを確認します。話者一覧から「ずんだもん」「ノーマル」を名前で検索してstyleIdを確定します。停止している場合は生成も停止し、代替音声は作りません。

```sh
node scripts/generate-flow-audio.mjs
# 既存監査結果を確認して更新する場合
node scripts/generate-flow-audio.mjs --replace
# 声かけ6件とタイマー終了案内の生成（初回）
node scripts/generate-flow-audio.mjs --extras
```

`reports/flow-audio-v2-audit.json` に全文、正規化後のvoiceText、speaker/style、kana、accent phrases、読みの検証結果、生成ファイル、byte数、秒数を保存します。生成ツールは既存監査ファイルがある場合、明示的な `--replace` なしで上書きしません。

声かけ・タイマーの同じ監査項目は `reports/flow-extras-audio-audit.json` に保存します。

音声クレジット：**VOICEVOX:ずんだもん**

## チャットと追加音声設定

`/chat` はテキストまたはマイクで質問できます。返答ルールは `lib/mockReplyRules.ts`、将来のAI API接続箇所は `lib/generateWillReply.ts` です。APIキーをブラウザへ置かないでください。

チャットの設定でブラウザ標準音声やローカルVOICEVOXを選べます。VOICEVOX合成は `/api/voicevox/tts` を経由し、利用できない場合にチャットや編集原稿は標準音声を使います。この設定は自動進行の録音案内には影響しません。

ローカル合成には `.env.example` の `VOICEVOX_ENGINE_URL` を参照してください。VercelのサーバーからローカルPCのENGINEには接続できません。自動進行の生成済み音声はこの制限の影響を受けません。

## 検証

```sh
node scripts/test-flow.mjs
npx tsc --noEmit
npm run build
git diff --check
```

ブラウザ監査はPlaywrightが利用できる環境で実行します（アプリに実行時依存は追加していません）。

```sh
WILL_AUDIT_URL=http://127.0.0.1:3001 \
WILL_PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
node scripts/audit-flow-browser.mjs
```

必要なら `WILL_CDP_URL` で既存Chromiumに接続できます。実際のWAVをdecode/playし、時刻を進めて全イベント順を検証します。結果は `reports/flow-v6-browser-audit.json` と `reports/flow-v6-*.png` です。`scripts/audit-flow-ux.mjs` は音量の実測と9状態×2サイズ、`scripts/audit-flow-cancellation.mjs` は遅延応答・実VOICEVOX・標準音声のキャンセルを検証します（後者2つの実VOICEVOX検証にはローカルENGINEが必要です）。

## Preview運用

既存feature branchのPRを更新し、Git連携が生成するVercel Previewを確認します。mainへのmergeやProductionへのデプロイは、Preview確認後の別作業です。

### 進行画面の操作と音量

時計の操作は「進行を一時停止 / 進行を再開」、聞き直しは「もう一度聞く」、音声とチャイムだけを止める操作は「今の音声を止める」です。「開催設定」の「自動進行を終了」は確認後にセッションを削除して開始前へ戻ります。「次」は残り時間のピル付きブロック、「その次」は控えめな枠付き行で表示し、「全体の進行」を開いて全体確認・移動を行います。

右上の設定に共通の「音声音量」0〜100%を置いています。録音・VOICEVOX・チャイムには再生中も即座に反映し、生成待ちのVOICEVOXにも最新値を使用します。編集した案内の標準音声は次の再生から反映します（案内文の編集欄に明記）。保存キーは既存の `will-recorded-volume` を引き継ぎます。チャイムは音程変更前の3打ベルへ戻しています。

自動進行の時計監視は音声コールバックから独立しています。「今の音声を止める」は現在の再生シーケンスだけを取り消し、発火済みイベントや将来の再生資格は変更しません。進行操作と音声操作を分け、軽量SVGのpause/play/replay/stopを文字ラベルと併用します。

`node scripts/audit-flow-playback.mjs` で停止後の自然な次イベント再生、チャイム待機キャンセル、10秒のpause、音量0.3、callback更新の競合を実ブラウザで監査します。テストfixtureはアプリへ配信せず、一時bundleにだけ使用します。

現在音声の状態は playing / stopped-manually / waiting / paused-by-flow / ended として管理し、未来イベントの再生許可とは独立させます。進行の再開は時計を再開して waiting に戻り、中断WAVは自動再生しません。pause中の明示的な聞き直しは利用できます。

画面の音声状態は「待機中 / 再生中」の2種類です。手動停止後の説明は2.5秒で消え、恒久的なミュート表示にはしません。声かけを押すと、現在音声に加えチャイム後の待機中WAVも取り消して声かけに切り替え、未来イベントは通常どおり再生します。

`node scripts/audit-flow-extras.mjs` は7WAV、共通音量、タイマー終了、声かけと自動案内の競合を検証します。`node scripts/audit-flow-design.mjs` は390×844 / 480×920の情報階層、初期表示内の操作、停止の一時フィードバック、開催設定の確認操作を検証します。

右上の設定は音声音量、チャイムのON/OFFと「チャイムを試聴」、音声テストの「テスト再生」、アプリについてをまとめています。開始前のカードから重複した試聴・音声テスト・コート選択を除きました。チャイムの保存キーは既存のものを継続し、どちらの進行方法でも試聴できます。
